# PROTOCOL-REVIEW — CPP v1.0 Deterministic Core Audit

- **Scope:** `protocol/models.py`, `protocol/canonical.py`, `protocol/__init__.py`, `tests/test_protocol.py`, cross-checked against `docs/decisions/ADR-0005-packet-schema-v1.md` and `docs/decisions/ADR-0003-determinism-model.md`.
- **Environment:** pydantic 2.14.1, CPython.
- **Method:** static read + targeted execution of the frozen core (no code modified).

## Findings

| ID | Sev | Location | Description | Suggested fix |
|----|-----|----------|-------------|---------------|
| P-01 | S1 | `protocol/canonical.py:42-52` | `_dumps_number` uses Python `repr()`, not the ECMAScript `Number::toString` algorithm required by RFC 8785 §3.2.2.3. Verified divergences: `1e16` → `"1e+16"` (JCS: `"10000000000000000"`), `1.2345678901234568e17` → `"1.2345678901234568e+17"` (JCS: `"123456789012345680"`), `1e-5` → `"1e-05"` (JCS: `"0.00001"`), `1e-7` → `"1e-07"` (JCS: `"1e-7"`, note zero-padded exponent). Any float in `[1e16,1e21)` or `< 1e-4` (e.g. `ContextBlock.confidence = 0.00001`) hashes to different bytes than a compliant verifier, breaking the Semantic Parity Gate / cryptographic replayability. The docstring example (`1e21`) is actually correct; the real gaps are the ranges above. | Replace `_dumps_number` with a compliant ECMAScript formatter — either the `rfc8785` package (`rfc8785.dumps`) or implement the §3.2.2.3 thresholds (decimal for `[-6, 21)` exponent range, otherwise exponent form with no leading-zero padding). |
| P-02 | S2 | `protocol/canonical.py:63-66` | `_serialize` dispatches on `isinstance(obj, int)`, which is true for `MemoryTier` (declared `(int, Enum)`). `str(MemoryTier.ledger)` is `"MemoryTier.ledger"` (plain-`Enum.__str__`), so `canonicalize(MemoryTier.ledger)` returns `b'MemoryTier.ledger'` — invalid JSON and a wrong hash. Reachable whenever a caller canonicalizes a `model_dump()` (python mode) payload; the current packet path avoids it only because `packet_content_hash` uses `mode="json"`. | Handle `enum.Enum` before `int`: `if isinstance(obj, Enum): return _serialize(obj.value)`. Optionally assert callers pass JSON-mode dumps. |
| P-03 | S2 | `protocol/canonical.py:104-106` vs `ADR-0005:87-88` | Preimage mismatch between ADRs. ADR-0005 Rule 1 says `content_hash` covers the packet **excluding `hashes.signature` only**; `packet_content_hash` empties the entire `hashes` block (per ADR-0003 §5), also excluding `content_hash` and `key_id`. ADR-0005's literal wording is self-referential (it would include `content_hash` in its own preimage, which is impossible). The code follows ADR-0003, so a verifier implementing ADR-0005 computes a different hash. | Amend ADR-0005 Rule 1 to match ADR-0003 ("empty the entire `hashes` block before hashing"), or change the code if ADR-0005 is authoritative. |
| P-04 | S2 | `protocol/canonical.py:87-93` vs `ADR-0005:80` | Hash format mismatch. `sha256_hex`/`packet_content_hash` return a bare 64-char hex, but ADR-0005 specifies `content_hash: "sha256:…"` (and `signature: "ed25519:…"`). The spike's block helper prefixes `"sha256:"` for `ContextBlock.content_hash`, so packet-level and block-level hash formats are internally inconsistent. Verified: `p.hashes.content_hash.startswith("sha256:") == False`. | Return `f"sha256:{hexdigest}"` from `packet_content_hash`, or define the wire format explicitly; add a `pattern` validator on `Hashes.content_hash`. |
| P-05 | S2 | `protocol/models.py:237` | `ContextPacket.total_tokens` is only `ge=0`; it is never checked against `budget.hard_total_tokens` or the summed tier token counts, despite ADR-0005 Rule 2 (`total_tokens + reserve_used <= hard_total_tokens`). Verified: `total_tokens=999999` accepted with `hard_total_tokens=4000`. | Add a `model_validator(mode="after")` asserting `total_tokens <= budget.hard_total_tokens` (and optionally `== tier0 tokens + Σ tier1-3 token_estimate`). |
| P-06 | S2 | `protocol/models.py:102-106, 170-172` | Tier-1 ordering invariant (ADR-0005 Rule 3: ascending by `source_event_seq`) is not enforced. Verified: `build_packet(2, (b2, b1))` accepted `block_id` order `['blk_2','blk_1']`. KV-cache prefix matching and replay correctness depend on this order. | Add a validator on `Tier1Ledger` (and `Tier3Register.observations`) asserting non-decreasing `source_event_seq` and unique `block_id`. |
| P-07 | S2 | `protocol/models.py:17-18, 89-90, 254` | Determinism gap: `observed_at`/`valid_from` default to `_now()` (wall clock), so two otherwise-identical packets built at different times produce different `content_hash`, conflicting with ADR-0003 ("same inputs → same bytes") unless every caller pins timestamps. The spike only passes because it reuses the same block objects. | Make `observed_at`/`valid_from` required (derive from the source event) or explicitly document that only pinned inputs are replay-comparable; add a test that constructs blocks independently and asserts equal hashes. |
| P-08 | S3 | `protocol/models.py:104-105` | `_content_or_pointer` only rejects both-`None`; it does not enforce pointer-vs-content semantics: `content=""` **and** `ref_uri=""` both pass; it does not require `ref_uri` when `block_kind`/`fidelity == pointer`; and `content_hash` is never tied to `content`. Verified both empty strings accepted. | Reject empty strings; require non-empty `ref_uri` when `block_kind==pointer`/`fidelity==pointer`; optionally verify `content_hash == "sha256:" + sha256(content)`. |
| P-09 | S3 | `protocol/models.py:86` | `confidence: float = 1.0` has no bounds; verified `confidence=-5.0` and `99.0` are accepted. | `Field(default=1.0, ge=0.0, le=1.0)`. |
| P-10 | S3 | `protocol/models.py:117-131` | `TokenBudget` fields have no `ge=0`; `_sums` only checks the sum, so `TokenBudget(hard_total_tokens=-100, tier0=-100, tier1=0, tier2=0, tier3=0, reserve=0)` passes. | Add `Field(ge=0)` to each budget field. |
| P-11 | S3 | `protocol/models.py:90-91` | No cross-validation that `valid_from <= valid_to`; verified inverted interval (`valid_from=2030`, `valid_to=2020`) accepted. | Add a `model_validator` asserting the interval when `valid_to` is set. |
| P-12 | S3 | `protocol/models.py:225` | `cpp_version: str = "1.0"` is unconstrained; a `"2.0"` packet is accepted and hashed, unlike the frozen v1.0 contract. | `cpp_version: Literal["1.0"] = "1.0"`. |
| P-13 | S3 | `protocol/models.py:34-38, 82-84` | Lax int/enum coercion: `MemoryTier(True)`/`memory_tier=True` → `ledger`, `MemoryTier(1.0)` → `ledger`, and `token_estimate=True` → `1`; booleans and integral floats silently become ints. | Use `StrictInt`/strict numeric fields, or a field validator rejecting `bool`/`float` for int fields. |
| P-14 | S3 | `protocol/canonical.py:109-122`, `tests/test_protocol.py:12-16` | The self-check and tests only cover decimals that agree with ECMAScript (`1.0`, `-0.0`, `0.5`); the divergent ranges from P-01 are untested, so the JCS non-compliance has no failing check. | Add RFC 8785 Appendix B vectors: `canonicalize(1e16) == b"10000000000000000"`, `canonicalize(1e-5) == b"0.00001"`, `canonicalize(1e-7) == b"1e-7"`. |
| P-15 | S3 | `protocol/models.py:100, 252` | `counterfactual_meta: dict[str, Any]` and `WorkflowEvent.payload: dict[str, Any]` are unconstrained; `Any` can hold non-canonicalizable values (sets, naive `datetime`, `Decimal`) that raise only later inside `canonicalize`. | Constrain the value types or validate JSON-serializability at model validation. |

## Verified correct

- **JCS string escaping** (`canonical.py:29-39`): short escapes for `" \ \b \f \n \r \t`, lowercase `\u00xx` for remaining C0 controls, and DEL/non-ASCII emitted literally as UTF-8 — matches RFC 8785 §3.2.2.2 / `JSON.stringify`.
- **UTF-16 key ordering** (`canonical.py:55-57, 77`) correctly compares unsigned 16-bit code units and handles non-BMP characters via surrogate pairs (astral code units sort below `0xE000–0xFFFF` per RFC 8785, unlike code-point order); verified `{"\u20ac":1,"z":2}` → `{"z":2,"\u20ac":1}`.
- **No insignificant whitespace / stable separators** in `_serialize`; `content_hash` is round-trip deterministic for equal inputs.
- **`extra="forbid"`** (`models.py:14`) works: constructing `ContextPacket` with an unknown field raises `ValidationError` (ADR-0005 Rule 4).
- **No mutable defaults**: every collection defaults to a tuple/`None`/`default_factory`; default model instances (`Tiers`, `Tier1Ledger()`, etc.) are frozen and shared safely.
- **`TokenBudget` defaults and `from_base`** proportions (15/25/5/45/10) sum exactly to `hard_total_tokens` for `base % 20 == 0`; `from_base(3999)` raises; defaults sum to 4000.
- **`packet_content_hash` is self-reference-free and idempotent**: the preimage is independent of the placeholder `content_hash`/`signature`, and `packet_content_hash(p) == p.hashes.content_hash` holds (`test_signature_excluded_from_hash`).
- **Enum membership** (`MemoryTier` ∈ {0,1,2,3}; `BlockKind`/`Fidelity`/`LifecycleStatus`/`CreatorType` StrEnums) matches ADR-0005 exactly.
- **Frozen models** reject attribute mutation; `_serialize` rejects NaN/Infinity and non-string object keys, and orders `bool` before `int`.
