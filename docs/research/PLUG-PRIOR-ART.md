# Plug Prior Art — What History Says About Shipping "The Plug"

- **Date:** 2026-10-17. **Scope:** integration plays in agent memory, context engineering, and LLM infrastructure, 2024–Oct 2026; lessons for a ~10-minute-install local plug.
- **Method:** web research only, primary sources preferred (vendor docs, GitHub, funding PRs, official blogs). No code changed. Anything not verifiable is marked **[UNVERIFIED]**; claims from vendor marketing are marked as such.

### Questions this document answers

- **Who has tried "plugging into" agents, and how did it go?** → §1.1–§1.4 (memory vendors, MCP servers, gateways, compression proxies).
- **What makes a 10-minute install stick?** → §2.
- **Post-mortems: which integration plays died, and why?** → §3.
- **Proxy vs MCP vs native integration — which plug shape?** → §4.
- **What should Context Fabric build (and explicitly refuse)?** → §5.

This is decision input for the plug shape; it is not a request to change code.

## Blunt read (before the evidence)

1. **The OpenAI-compatible-proxy shape is strongly validated** — every major gateway uses exactly this interface (LiteLLM, Bifrost, Portkey, CLIProxyAPI, Claude Code Router), because "change one base URL, zero code changes" is the only install that survives contact with real users ([docs.litellm.ai](https://docs.litellm.ai/docs/simple_proxy), [github.com/maximhq/bifrost](https://github.com/maximhq/bifrost), [github.com/router-for-me/CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)).
2. **But the generic "context compression proxy" slot is already filling fast:** Compresr Context Gateway (YC-backed, 645★, Feb 2026), Headroom, Kompact, OpenCompress, NLProxy, plus Anthropic's own server-side context editing. If our pitch is "smaller context, cheaper," we are late ([github.com/Compresr-ai/Context-Gateway](https://github.com/Compresr-ai/Context-Gateway), [github.com/thebigby10/headroom](https://github.com/thebigby10/headroom), [opencompress.ai](https://www.opencompress.ai/integrate/api), [anthropic.com/news/context-management](https://www.anthropic.com/news/context-management)).
3. **Our exact beachhead has a first-party-adjacent competitor:** vLLM Semantic Router (official `vllm-project` repo, 6.2k★, curl-install, AMD/NVIDIA/Red Hat/Microsoft ecosystem, episodic memory + context policy in its papers). It routes *models*; we compile *context* — but it is one feature release away from us ([github.com/vllm-project/semantic-router](https://github.com/vllm-project/semantic-router), [vllm-semantic-router.com/white-paper.pdf](https://vllm-semantic-router.com/white-paper.pdf)).
4. **Local-first components get deprioritized** by cloud businesses: Zep killed Community Edition, Mem0 archived its local MCP server and is sunsetting OpenMemory, Motorhead is dead. Local-first *is* our wedge precisely because incumbents keep abandoning exactly that ([getzep.com blog](https://www.getzep.com/blog/announcing-a-new-direction-for-zeps-open-source-strategy/), [github.com/mem0ai/mem0-mcp](https://github.com/mem0ai/mem0-mcp), [getmetal/motorhead](https://github.com/getmetal/motorhead)).
5. **MCP is the reach channel, the proxy is the control channel.** MCP gets you into every client (38–41k servers in the official registry; 122M package installs/month) but tools are *model-invoked* — the agent decides whether to call them. A proxy injects unconditionally and controls the KV prefix. Ideal plug = proxy + thin MCP surface for query/audit, not either/or ([mcphq.ai/state-of-mcp](https://mcphq.ai/state-of-mcp), [gravity.fast](https://gravity.fast/data/mcp-adoption-statistics/), [docs.mem0.ai/platform/mem0-mcp](https://docs.mem0.ai/platform/mem0-mcp)).

## 1. Plug plays that have been tried, and how they fared

### 1.1 Memory vendors plugging into frameworks

- **Mem0** is the success case: $24M across seed+Series A (Oct 2025), 41k★ and 14M downloads at raise time, API calls 35M (Q1'25) → 186M (Q3'25), and **exclusive memory provider for AWS's Agent SDK** — the biggest distribution win in the category. Current site claims 62.5k★. Vendor claims native integrations in CrewAI, Flowise, Langflow (their words) ([techcrunch.com](https://techcrunch.com/2025/10/28/mem0-raises-24m-from-yc-peak-xv-and-basis-set-to-build-the-memory-layer-for-ai-apps), [mem0.ai/series-a](https://mem0.ai/series-a), [mem0.ai](https://mem0.ai/)).
- **Zep** raised a seed/Y Combinator W24 and shipped a strong benchmark story (LoCoMo 94.7%, LongMemEval 90.2%, ~155–162ms retrieval) — but **ended Zep Community Edition in April 2025**, candidly admitting it "under-invested in the open-source version" under open-core and felt "uneasy" gating features. Open source effort collapsed to Graphiti (20k★ by Nov 2025), with a Memory MCP Server reaching GA on managed cloud/BYOC in Aug 2026 ([getzep.com](https://www.getzep.com/), [announcement](https://www.getzep.com/blog/announcing-a-new-direction-for-zeps-open-source-strategy/), [Graphiti 20k post](https://blog.getzep.com/graphiti-hits-20k-stars-mcp-server-1-0/), [agent-memory-mcp](https://blog.getzep.com/agent-memory-mcp)).
- **Letta (MemGPT)** renamed (Sept 2024), then re-architected its agent loop to `letta_v1_agent` (Oct 2025), moved active development to a new Letta Agent repo (the old server is now explicitly "legacy"), and pivoted the brand toward a CLI/desktop "Letta Agent" with research cadence (Context Constitution Apr 2026, Context Repositories Feb 2026). Funded and alive, but the product surface has moved three times in two years ([letta.com](https://www.letta.com/), [letta-v1-agent](https://www.letta.com/blog/letta-v1-agent), [github.com/letta-ai/letta](https://github.com/letta-ai/letta)).
- **Framework-side churn is a tax:** LangChain deprecated all its classic memory classes (`ConversationBufferMemory` etc., deprecated since 0.3.x, removal in 2.0.0) in favor of `create_agent` + checkpointers + Store, and launched LangMem as the successor (Feb 2025). Any adapter built into the old memory API is dead code now ([langchain reference](https://reference.langchain.com/python/langchain-classic/memory/buffer/ConversationBufferMemory), [LangMem launch](https://blog.langchain.com/langmem-sdk-launch)).
- **AutoGen — the framework itself was retired** (maintenance mode Oct 2025; now fully archived and merged into Microsoft Agent Framework). An adapter strategy against AutoGen would have been a dead end within a year ([github.com/microsoft/autogen](https://github.com/microsoft/autogen), [commit](https://github.com/microsoft/autogen/commit/027ecf0a379bcc1d09956d46d12d44a3ad9cee14)).

### 1.2 MCP memory servers

- The **official reference memory server** (knowledge-graph, still primitive) has **500K+ Docker pulls** via the Docker MCP catalog — proof of demand for local memory tooling, not of quality ([github.com/modelcontextprotocol/servers](https://github.com/modelcontextprotocol/servers/tree/main/src/memory), [hub.docker.com](https://hub.docker.com/mcp/server/memory/overview)).
- **Mem0's** local `mem0-mcp` is now a **public archive** ("no longer actively maintained"); the official path is a hosted cloud MCP server at `mcp.mem0.ai`; OpenMemory is being **sunset** in favor of the self-hosted server. Even the memory leader keeps changing its plug story ([mem0-mcp](https://github.com/mem0ai/mem0-mcp), [docs.mem0.ai](https://docs.mem0.ai/platform/mem0-mcp), [openmemory README](https://github.com/mem0ai/mem0/tree/main/openmemory)).
- **Zep's** Memory MCP server GA (Aug 2026) is the current enterprise answer: "one agent memory across Claude, ChatGPT, and your custom agents" ([blog.getzep.com](https://blog.getzep.com/agent-memory-mcp)).
- Ecosystem scale: official registry launched **Sept 8, 2025**; by **Oct 10, 2026** it listed **41,400 servers** (one tracker counts 38,107 published by Sept 2026 with **122M package installs/month**; another shows the upstream `modelcontextprotocol/servers` repo at 86k★). TypeScript MCP SDK npm downloads hit **76.7M/week**, PyPI `mcp` **61M/week** (Oct 2026) ([gravity.fast](https://gravity.fast/data/mcp-adoption-statistics/), [mcphq.ai](https://mcphq.ai/state-of-mcp), [tech-insider.org](https://tech-insider.org/ie/model-context-protocol-mcp-update-2026/)).
- But MCP has structural limits: **86% of ranked servers are stdio-only** (invisible to ChatGPT), **53% use long-lived API keys**, and a registry audit found **15,465 servers with effectively zero governance** ([top-mcps.com](https://top-mcps.com/guides/state-of-mcp-q3-2026), [WorkOS/Ox Security](https://workos.com/blog/mcp-governance-gap)).
- MCP was donated to the **Agentic AI Foundation** under the Linux Foundation (Dec 9, 2025), alongside AGENTS.md — the neutral-governance trend favors protocol-shaped products over single-vendor ones ([agents.md](https://agents.md/), [openai.com](https://openai.com/index/agentic-ai-foundation/)).

### 1.3 OpenAI-compatible gateways (routing/observability)

- **LiteLLM** is the category's dominant OSS layer: 140+ providers, 1,892 models, **60k+★, 511M+ Docker pulls, 92M+ PyPI downloads/month**, MIT, one-command quickstart, and an MCP gateway on top ([litellm.ai/about](https://www.litellm.ai/about), [quickstart](https://docs.litellm.ai/docs/simple_proxy)).
- **Portkey** (in-path AI gateway + governance): $15M Series A Feb 2026; 500B+ tokens/day, 24k orgs, $180M annualized spend under management; **acquired by Palo Alto Networks** (announced Apr 30, 2026) — The New Stack characterized it as a $700M-class bet. The gateway position is strategically valuable enough to be bought by a security giant ([portkey.ai/blog/series-a-funding](https://portkey.ai/blog/series-a-funding/), [PR Newswire](https://www.prnewswire.com/news-releases/palo-alto-networks-to-acquire-portkey-to-secure-the-rise-of-ai-agents-302759436.html), [thenewstack.io](https://thenewstack.io/palo-alto-portkey-ai-gateway/)).
- **Helicone** (observability proxy): acquired by Mintlify (announced Nov 26, 2025) ([helicone.ai/changelog](https://www.helicone.ai/changelog), [YC](https://www.ycombinator.com/companies/helicone)).
- **Bifrost** (Maxim AI, Go, Apache-2.0): npx/docker one-command, markets <200µs overhead and "50x faster than LiteLLM"; star counts range ~5.4k (repo snapshot) to ~8.9k (topic listings) across 2026 — treat as several-thousand★ and rising ([github.com/maximhq/bifrost](https://github.com/maximhq/bifrost)).
- **Claude Code Router** (solo OSS project): a local gateway in front of coding agents — **37.7k★**, desktop app + npm CLI + Discord, routing/failover/observability. Proof that the "one local endpoint for every agent" plug can get massive adoption without a company; it is routing, not context ([github.com/musistudio/claude-code-router](https://github.com/musistudio/claude-code-router)). CLIProxyAPI (wrap CLI subscriptions as OpenAI/Gemini/Claude APIs) sits at **55.5k★** ([github.com/router-for-me/CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)).

### 1.5 First-party platform absorption (the biggest structural risk)

- **Anthropic shipped context editing + a memory tool server-side** (Sept 29, 2025): context editing alone gave **+29%** on their agentic-search eval, combined with the memory tool **+39%**; GA-era docs show it paired with server-side **compaction**. Every context-compression proxy loses its simplest value proposition to this ([anthropic.com/news/context-management](https://www.anthropic.com/news/context-management), [platform.claude.com docs](https://platform.claude.com/docs/en/build-with-claude/context-editing)).
- **AGENTS.md got donated to the Linux Foundation** (Dec 2025) and is read natively by Codex/Copilot/Cursor/Windsurf et al. — the "context file" convention is already standardized; stand-alone file formats struggle to compete with it ([agents.md](https://agents.md/), [adoption snapshot](https://github.com/genno-whittlery/agent-notes/blob/main/2026-agents-md-standard.md)).
- Counter-evidence worth remembering: a 2026 arXiv study found repo context files **can hurt** — developer-provided files improved success only ~2.4% on average (statistically insignificant), LLM-generated files slightly *reduced* it (−0.5%/−2%, not significant), and overall cost rose >20% (+23% with LLM-generated files). "We add context" is not self-evidently good; it must be measured ([arXiv 2602.11988v3](https://arxiv.org/html/2602.11988v3)).

### 1.7 Cross-cutting patterns

- **Transport integrations outlive framework integrations.** Framework-native memory APIs died or were rewritten (AutoGen → MAF; LangChain memory → 2.0 removal), while base-URL proxies keep working across framework generations ([autogen](https://github.com/microsoft/autogen), [langchain reference](https://reference.langchain.com/python/langchain-classic/memory/buffer/ConversationBufferMemory), [litellm](https://docs.litellm.ai/docs/simple_proxy)).
- **Every funded winner owns an artifact or a channel.** Mem0 → AWS Agent SDK exclusivity; Zep → benchmark story + enterprise BYOC; LiteLLM → provider breadth; Claude Code Router → the local endpoint for coding agents. A plug that owns neither drifts until it pivots (Fixie) or dies (Motorhead) ([techcrunch.com](https://techcrunch.com/2025/10/28/mem0-raises-24m-from-yc-peak-xv-and-basis-set-to-build-the-memory-layer-for-ai-apps), [CCR](https://github.com/musistudio/claude-code-router), [fixie.ai](https://fixie.ai/), [motorhead](https://github.com/getmetal/motorhead)).
- **Compression is table stakes, not a wedge.** At least five surveyed proxies ship overlapping compression/compaction, and two advertise cache alignment explicitly; Anthropic does the simple half server-side for free ([Compresr](https://github.com/Compresr-ai/Context-Gateway), [Headroom](https://github.com/thebigby10/headroom), [Kompact](https://github.com/npow/kompact), [OpenCompress](https://www.opencompress.ai/integrate/api), [anthropic.com](https://www.anthropic.com/news/context-management)).
- **Local-first requires deliberate maintenance, because cloud businesses abandon it.** Zep CE, `mem0-mcp`, OpenMemory, Motorhead — four distinct local-first casualties in 18 months, each by a company whose revenue was elsewhere ([zep](https://www.getzep.com/blog/announcing-a-new-direction-for-zeps-open-source-strategy/), [mem0-mcp](https://github.com/mem0ai/mem0-mcp), [openmemory](https://github.com/mem0ai/mem0/tree/main/openmemory), [motorhead](https://github.com/getmetal/motorhead)).
- **Distribution follows the client ecosystem, not the vendor's website.** The winning install surface in 2026 is the client's own store: Claude plugins, Docker MCP catalog, registry one-click — with a repo one-command as the fallback ([claude.com](https://claude.com/blog/claude-marketplace), [Docker MCP](https://hub.docker.com/mcp/server/memory/overview), [LiteLLM quickstart](https://docs.litellm.ai/docs/simple_proxy)).

## 2. What makes a 10-minute install that sticks (evidence, not folklore)

- **Zero-code-change is the winning interface.** LiteLLM markets "no code changes"; Bifrost ships npx/docker one-liners; MCP clients install with `npx`/`uvx`; Claude Code Router sets one endpoint. The proxy pattern wins because integration cost ≈ setting one env var ([docs.litellm.ai](https://docs.litellm.ai/docs/simple_proxy), [Bifrost](https://github.com/maximhq/bifrost), [CCR quickstart](https://github.com/musistudio/claude-code-router)).
- **One-click packaging measurably lowers the bar.** Anthropic's MCP Bundles (`.mcpb`, Jun 2025; renamed Sept 2025) bundle all dependencies so install = download → double-click → Install, "no terminal, no configuration files." MCP installer conventions back this: `npx` is the primary install method for 40% of directory listings (209/520), `uvx` for 99 ([anthropic.com/engineering/desktop-extensions](https://www.anthropic.com/engineering/desktop-extensions), [mcptrove.com/report](https://mcptrove.com/report)).
- **Registries and marketplaces are now real distribution.** Claude Marketplace launched with **2,000+ plugins/connectors** (Sept 23, 2026) — and stopped accepting standalone `.mcpb` listings: the distribution unit is now the **plugin**, built on MCP + Agent Skills. Third-party directories (claudemarketplaces.com) claim **380k monthly visitors**. Docker's MCP catalog adds one-click installs with a verified-publisher trust layer ([claude.com/blog/claude-marketplace](https://claude.com/blog/claude-marketplace), [it-connect](https://www.it-connect.tech/claude-marketplace-grows-fast-anthropic-brings-2000-connectors-and-plugins-together/), [claudemarketplaces.com](https://claudemarketplaces.com/), [Docker MCP](https://hub.docker.com/mcp/server/memory/overview)).
- **Local runtime conventions set the beachhead's expectations:** Ollama = one command then an OpenAI-compatible API on `localhost:11434` (**~9M users**, $65M raise, Jul 2026; 52M monthly model downloads); LM Studio = GUI + OpenAI-compatible `localhost:1234/v1` (free for work since Jul 8, 2025). Our plug must feel like these: one command, localhost, no account ([Wikipedia/Ollama](https://en.wikipedia.org/wiki/Ollama), [toolradar](https://toolradar.com/guides/best-local-llm-tools), [pinggy.io](https://pinggy.io/blog/top_5_local_llm_tools_and_models/), [tech-insider.org](https://tech-insider.org/ollama-vs-lm-studio-vs-jan-2026/)).
- **Hands-on beats docs-only, but teams under-invest in it.** Instruqt/DMA's 2025 survey (n≈ hundreds of orgs; 72% rely on written docs, 67% on video): hands-on real-world training ranked the single most effective enablement method but only **32.9%** of orgs use it; **~60% report 1–3 months** before developers fully adopt new tooling. A 5-minute interactive demo is not decoration; it is the adoption mechanism ([instruqt.com](https://instruqt.com/state-of-developer-adoption-2025), [press release](https://instruqt.com/blog/instruqt-launches-state-of-developer-adoption-2025-report)).
- **Honest gap:** we found **no rigorous 2025–2026 study ranking HN/Reddit/X/Discord/YouTube** for dev-tool launch outcomes. Treat channel mix as judgment, not evidence. What is supported: GitHub + registry/marketplace presence + an OSS repo are table stakes; Discord/X links are standard in successful plugs (CCR, Mem0, MCPB ecosystem) **[UNVERIFIED as causal]** ([CCR README](https://github.com/musistudio/claude-code-router)).

## 4. Honest risk check: proxy vs MCP vs native integration

| Criterion | OpenAI-compatible proxy/sidecar | MCP server | Native framework integration |
|---|---|---|---|
| Install friction | One env var / one command; works with anything speaking `/v1` ([LiteLLM](https://docs.litellm.ai/docs/simple_proxy)) | `npx`/`uvx`/`.mcpb`; 86% stdio-only limits cloud reach ([top-mcps](https://top-mcps.com/guides/state-of-mcp-q3-2026)) | Highest: version pinning, framework churn ([AutoGen](https://github.com/microsoft/autogen), [LangChain](https://reference.langchain.com/python/langchain-classic/memory/buffer/ConversationBufferMemory)) |
| Can it *guarantee* context injection? | **Yes** — sits in the request path | **No** — model decides whether to call a tool ([Mem0 MCP docs](https://docs.mem0.ai/platform/mem0-mcp)) | Yes, but only inside that framework |
| Can it control KV/caching? | **Yes** — only place that sees and can stabilize the prefix & emit cache hints | No | Rarely |
| Distribution | GitHub, HN, package managers; proven at 37.7k★ (CCR) ([CCR](https://github.com/musistudio/claude-code-router)) | Registries + marketplaces: 41k servers, Claude/Docker directories ([gravity](https://gravity.fast/data/mcp-adoption-statistics/), [Claude Marketplace](https://claude.com/blog/claude-marketplace)) | Vendor SDKs; slow |
| Competition | Crowded: LiteLLM, Bifrost, Portkey, SR, Compresr… ([litellm](https://www.litellm.ai/about), [semantic-router](https://github.com/vllm-project/semantic-router)) | Crowded and low-trust (15k ungoverned) ([WorkOS](https://workos.com/blog/mcp-governance-gap)) | Fewer players; higher maintenance |
| Strategic value | Proven — gateways acquired (Portkey/PANW, Helicone/Mintlify) ([PANW PR](https://www.prnewswire.com/news-releases/palo-alto-networks-to-acquire-portkey-to-secure-the-rise-of-ai-agents-302759436.html)) | Real but commoditized | Low; you rent someone else's roadmap |

**Verdict:** the evidence supports the proxy as the **primary wedge** for local-GPU operators (guaranteed injection, cache control, zero-code install, proven interface), **plus a thin MCP surface** for query/audit/negative-knowledge tools where a model-invoked interface is fine, **plus exactly one native integration** as a demo (a base-URL override path counts as native). The generic compression features of the proxy are already commoditized; the wedge must be **fleet-level shared prefix + negative knowledge + audit receipts**, which none of the surveyed proxies ship. If CF's plug is only "compress the prompt," it should not be built — the evidence says that fight is over before we enter it.

## 5. So what for Context Fabric

Ranked, concrete, and including the things to refuse:

1. **Build the OpenAI-compatible sidecar first — with exactly one command.**
   `cfx serve --upstream http://localhost:8000/v1` (or `uvx contextfabric serve`) that compiles context on the wire and returns standard responses. Evidence: this is the only interface with universal local adoption (Ollama/LM Studio/vLLM all expose `/v1`) and the pattern behind the category's biggest OSS wins (LiteLLM 60k★, CCR 37.7k★) ([litellm.ai/about](https://www.litellm.ai/about), [CCR](https://github.com/musistudio/claude-code-router)).
2. **Make the demo the product: one repo, one command, before/after receipt in under 10 minutes.**
   Pre-register what the installer measures (tokens, KV peak, failure repeats). Evidence: hands-on is the most effective enablement method but the least used; most developers need weeks to adopt — the demo must carry adoption alone ([Instruqt](https://instruqt.com/state-of-developer-adoption-2025)). Ship a GIF/video and a single copy-pasteable curl.
3. **Lead with negative knowledge + cross-agent shared prefix, not compression.**
   Demo: agent A hits a dead end; agent B is hard-blocked; receipt attached; virtual-agent test shows byte-identical Tier-0/1 across role-divergent agents. None of Compresr/Headroom/Kompact/OpenCompress claim this; Anthropic's context editing and vLLM SR's routing don't share prefixes across agents ([Compresr](https://github.com/Compresr-ai/Context-Gateway), [Headroom](https://github.com/thebigby10/headroom), [anthropic](https://www.anthropic.com/news/context-management), [semantic-router](https://github.com/vllm-project/semantic-router)).
4. **Make cache-alignment table stakes, not your pitch.** Prefix stability, cache keys, and LMCache/CacheScout hints should be in v1 silently — Kompact and Headroom already advertise "Cache Aligner" features. We only win the comparison if the *shared* prefix is the differentiator ([Kompact](https://github.com/npow/kompact), [Headroom](https://github.com/thebigby10/headroom)).
5. **Do NOT become a gateway.** No multi-provider routing, no budgets, no failover dashboards, no model pinning. LiteLLM, Bifrost, Portkey, and vLLM SR own that, and Portkey's acquisition shows the ceiling is paid for by security/enterprise budgets we don't have ([PANW](https://www.prnewswire.com/news-releases/palo-alto-networks-to-acquire-portkey-to-secure-the-rise-of-ai-agents-302759436.html), [Bifrost](https://github.com/maximhq/bifrost), [vLLM SR](https://github.com/vllm-project/semantic-router)).
6. **Ship exactly one packaged distribution beyond the repo: a plugin/MCP bundle that carries the CLI.** The Claude Marketplace no longer accepts standalone `.mcpb` — the unit is a plugin (MCP + skills). Docker MCP catalog has one-click installs with signature verification. Do this for reach; keep the proxy as the mechanism ([Claude Marketplace](https://claude.com/blog/claude-marketplace), [it-connect](https://www.it-connect.tech/claude-marketplace-grows-fast-anthropic-brings-2000-connectors-and-plugins-together/), [Docker MCP](https://hub.docker.com/mcp/server/memory/overview)).
7. **Never gate the local path; never require an account.** Zep's own post-mortem says feature-gating OSS to upsell poisoned the well; Mem0 archived local wrappers. Our entire beachhead is people the cloud vendors keep orphan. Local compile, local verify, offline by default — telemetry opt-in ([Zep](https://www.getzep.com/blog/announcing-a-new-direction-for-zeps-open-source-strategy/), [mem0-mcp](https://github.com/mem0ai/mem0-mcp)).
8. **Publish one measured, honest integration demo against the strongest local baseline (vLLM APC + LMCache + Semantic Router where possible) and swallow the result.** The AGENTS.md study shows context additions can *hurt* quality and raise cost; the 10-minute plug must come with a number, not a narrative ([arXiv 2602.11988v3](https://arxiv.org/html/2602.11988v3)). README gets one table: tokens, KV peak, TTFT, task success, repeat-failure rate — CF vs the best available alternative, not vs naive broadcast.

### Explicitly do NOT, in v1

- Do not ship a cloud preview or a hosted control plane before the local path is boring (Mem0/OpenMemory arc).
- Do not build 8 framework adapters (ADR-0004 already forbids this; AutoGen's death validates it) — base-URL compatibility *is* the integration.
- Do not rewrite user prompts with a cheap token compressor (LLMLingua-style) as a headline feature — it breaks prefix caching and quality, and it is the commoditized half of the competition's feature list ([Kompact quality table](https://github.com/npow/kompact)).
- Do not fight vLLM SR for "the router in front of vLLM." Compose behind it or beside it; "CF compiles the prefix; SR/LMCache protects and routes it" is available positioning today ([vLLM SR docs](https://vllm-sr.ai/)).

### Watch list — what would falsify this recommendation

- If **vLLM Semantic Router ships cross-agent context compilation** (packet sharing, not just routing), the right move is to contribute upstream or position CF under it, not to compete with a first-party-adjacent sidecar ([semantic-router](https://github.com/vllm-project/semantic-router)).
- If **Anthropic/OpenAI extend context management to cross-agent shared prefixes or project-level verified context**, the accessible audience shrinks to local-OSS fleets and the plug's pitch should become audit/verification tooling ([anthropic.com](https://www.anthropic.com/news/context-management)).
- If the **Claude Marketplace/plugin path rejects vendor-neutral proxy wrappers**, redistribute via MCP registry + Docker MCP + direct repo, where CCR already proved 37.7k★ reach ([claude.com](https://claude.com/blog/claude-marketplace), [CCR](https://github.com/musistudio/claude-code-router)).
- If measured shared-prefix KV savings on a real vLLM fleet **do not clear ADR-0004's gates**, ship negative knowledge + audit receipts only, or stop before building the sidecar — the evidence does not support building it on compression alone.

### Bottom line

The plug's *shape* (OpenAI-compatible local sidecar, one-command install, proxy-first + thin MCP) is the best-supported choice in the evidence. The plug's *pitch* must not be "smaller context" — that is contested by funded startups and by Anthropic itself — it must be "one signed packet of shared truth, fleet-wide KV savings, and failure memory that no vendor is maintaining locally." Build the sidecar; demo negative knowledge in five minutes; refuse the gateway and the cloud detour.
