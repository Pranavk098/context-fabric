# External Research Round C: Cutting Coding-Agent Context Tokens Without Losing Accuracy (2025–2026)

**Date**: 2026-10-18  
**Scope**: External empirical evidence (2023–2026 literature and engineering reports, focusing on 2025–2026 SOTA) mapped against Context Fabric internal benchmarks (`B4`, `B4-V3`, `PILOT-MECH`, `B4-EXPLORE`, `B7-FOLD-IN`).  
**Verification Policy**: Every external quantitative claim below is cited to a primary URL opened on `2026-10-18`; any metric not reported in the opened primary source is explicitly marked `"not verified"`.

## Executive Summary (10 Bullets)

1. **Query-blind token compression and static body-stripping fail on code; query-conditioned line/block pruning succeeds.** General NL token compressors (`LLMLingua-2`) drop SWE-bench Verified resolve rates by **-8 pp** (`62% -> 54%`), whereas task-conditioned code line/block pruners (**SWE-Pruner**, **LongCodeZip**) cut context tokens by **23–54% in multi-turn agents** and **4.3x–14.8x in single-turn tasks** with **$\ge 0$ accuracy delta** ([SWE-Pruner](https://arxiv.org/html/2601.16746v1), [LongCodeZip](https://arxiv.org/html/2510.00446v1), accessed 2026-10-18).
2. **AST skeletons/signatures work for *localization*, never as the sole *repair/QA* input.** **Agentless**, **LocAgent**, and **Aider** all use AST/CTags signatures or folded views strictly as a navigation index to locate target entities, then always expand **uncompressed code windows or full function bodies** before asking the LLM to reason or edit ([Agentless](https://arxiv.org/html/2407.01489v1), [LocAgent](https://arxiv.org/html/2503.09089v1), [Aider RepoMap](https://aider.chat/docs/repomap.html), accessed 2026-10-18).
3. **Small models (0.5B–0.6B) excel as *compressors/skimmers*, but fail as *readers* of abstracted stubs.** **LongCodeZip** (`Qwen2.5-Coder-0.5B`) and **SWE-Pruner** (`Qwen3-Reranker-0.6B`) prove sub-1B models accurately score code relevance, but when small models (`0.5B–7B`) must *answer from* compressed/skeletonized code, they suffer severe degradation unless function bodies remain intact ($R_{\text{fine}}=1.0$ on RepoQA) ([LongCodeZip](https://arxiv.org/html/2510.00446v1), [SWE-Pruner](https://arxiv.org/html/2601.16746v1), accessed 2026-10-18).
4. **This directly explains Context Fabric's `B4` and `B4-v3` results.** Our mechanical `.cfx` compiler stripped method bodies and symbol-to-module import associations into static ~4k AST packets and asked `0.5B`/`1.5B` reader models to answer implementation questions (`21/36` in `B4`, `7/20` vs `11/20` BM25 retrieval in `B4-v3`), violating the field's universal *skeleton-to-locate, raw-body-to-solve* rule (`docs/engineering/B4-RESULT.md`, `docs/engineering/B4-V3-RESULT.md`, `docs/engineering/B4-EXPLORE.md`).
5. **Hybrid "retrieve then compress" beats plain retrieval *at equal budget* only when compression is query-conditioned.** At a fixed 2,000-token budget on `Qwen2.5-Coder-7B`, **LongCodeZip** (**57.55 ES / 32.40 EM** at 4.3x compression) outperforms plain **Function-RAG** (**52.79 ES / 26.00 EM** at 3.1x compression) because pruning dead blocks inside top functions frees budget to pack more required functions ([LongCodeZip](https://arxiv.org/html/2510.00446v1), accessed 2026-10-18).
6. **In multi-turn coding agents, tool observations (`read`/`grep`/`test`) are 59–84% of all tokens — the #1 cost lever.** Environment observations constitute **~84%** of average `SWE-agent` turn tokens ([Lindenbauer et al.](https://arxiv.org/html/2508.21433v1), accessed 2026-10-18), `read` operations alone consume **67.5–76.1%** of total trajectory tokens ([SWE-Pruner](https://arxiv.org/html/2601.16746v1), accessed 2026-10-18), and tool outputs occupy **~59%** of peak KV cache ([ReFold](https://arxiv.org/html/2610.07863v1), accessed 2026-10-18).
7. **Simple observation masking beats LLM trajectory summarization.** Masking tool observations older than $M=10$ turns cuts SWE-bench Verified cost by **>50%** (`$1.29 -> $0.61` on `Qwen3-Coder-480B`) and improves solve rate (`53.8% -> 54.8%`), whereas LLM summarization triggers a **+13–15% "trajectory elongation" penalty** because smoothed summaries hide dead-end failure signals ([Lindenbauer et al.](https://arxiv.org/html/2508.21433v1), accessed 2026-10-18).
8. **Per-step prompt mutation destroys prefix caching and inflates real API cost.** Naive sliding-window masking mutates the prefix every turn, collapsing prefix-cache hit rates from **84% to 23%** and adding **5.1 cents/task (31% of total cost)** in lost cache discounts ([ReFold](https://arxiv.org/html/2610.07863v1), accessed 2026-10-18); preserving cache boundaries saves **41–80%** in agentic API cost ([Lumer et al.](https://arxiv.org/html/2601.06007v1), accessed 2026-10-18).
9. **Chunked, reversible inter-turn folding (`ReFold`) solves both KV bloat and cache invalidation.** Deduplicating repeated file/search reads into signature stubs and folding completed turns only every $k=3$ steps (with 1-step lossless `restore <step>`) keeps prefix-cache hits at **87%**, cuts tokens by **18–60%**, halves peak KV cache (**30–58% reduction**), avoids **up to 92% of forced compactions**, and under high concurrency (`w=48`) boosts solved tasks from **7/50 to 32/50** ([ReFold](https://arxiv.org/html/2610.07863v1), accessed 2026-10-18).
10. **Context Fabric's winning 2026 thesis is a Cache-Aligned Trajectory & Handoff MMU + Auditable Governance Layer.** We must drop one-shot static body-stripping when context fits, keep a pinned shared Tier-0 prefix, shift compression to **query-conditioned `read`-output skimming + $k$-step reversible `ctx://` folding**, and prove it on **Resolved Tasks per Uncached-$1 / Peak KV GB** at $\Delta\text{Accuracy} \ge 0$.

## Q1. State of the Art (2025–2026) for Accuracy-Preserving Context Reduction in Coding & Multi-Agent Systems

### Key Findings Across Seven Method Families
1. **Code-Specific Prompt Compression (`LongCodeZip`, `SWE-Pruner`) vs NL Token Drop (`LLMLingua` family)**:
   - Token-level natural-language compressors (`LLMLingua`, `LongLLMLingua`, `LLMLingua-2`) break code syntax and indentation; when plugged into `Mini SWE Agent` on SWE-bench Verified-50, `LLMLingua-2` drops resolution by **-8.0 pp** (`62% -> 54%`) ([SWE-Pruner](https://arxiv.org/html/2601.16746v1), accessed 2026-10-18).
   - **LongCodeZip** (Oct 2025) preserves syntactic blocks via two stages: coarse function ranking by instruction-conditioned perplexity (AMI) and fine intra-function block pruning via perplexity spike detection + 0/1 knapsack. It achieves up to **5.6x compression** with zero accuracy loss on `Qwen2.5-Coder-7B`, `DeepSeek-Coder-6.7B`, `GPT-4o`, and `Claude-3.7-Sonnet`, and **improves RepoQA accuracy above uncompressed full context** on `GPT-4o` (`88.9`) and `Claude-3.7-Sonnet` (`90.7`) ([LongCodeZip](https://arxiv.org/html/2510.00446v1), accessed 2026-10-18).
   - **SWE-Pruner** (Jan 2026) trains a lightweight `Qwen3-Reranker-0.6B` line-level skimmer with a CRF head (`<100ms` latency for 8k tokens) driven by an explicit agent-emitted `Goal Hint` (`context_focus_question`). On SWE-bench Verified, it reduces tokens by **23.8–38.4%** and turns by **18–26%** with `<1%` delta (and **+2.0 pp** on the 50-task ablation slice) ([SWE-Pruner](https://arxiv.org/html/2601.16746v1), accessed 2026-10-18).
2. **Repo Maps & Hierarchical Localization (`Aider`, `Agentless`, `SWE-agent`)**:
   - **Aider** builds a tree-sitter CTags call/dependency graph ranked by **PageRank** personalize-weighted by chat mentions, binary-searching a dynamic token budget (default **1,024 tokens**, expanding when no files are in chat) to emit signatures/call sites *only* as a repository map ([Aider RepoMap](https://aider.chat/docs/repomap.html), accessed 2026-10-18).
   - **Agentless** (Jul 2024) replaces autonomous tool loops with a 3-stage pipeline: (1) file tree -> AST skeleton headers of top-$N$ files -> full code of localized functions, (2) $\pm 10$-line uncompressed edit windows for search-and-replace diffs, and (3) reproduction test filtering, solving **27.33% (82/300)** in v1 HTML (**32.00%, 96/300** in updated abstract) on SWE-bench Lite at **$0.34–$0.70/issue** ([Agentless](https://arxiv.org/html/2407.01489v1), [abs](https://arxiv.org/abs/2407.01489), accessed 2026-10-18).
   - **SWE-agent** (May 2024) introduces an Agent-Computer Interface (ACI) with a **100-line file viewer**, line-numbered search capped at 50 results, and linter-guarded edits, reaching **12.47% (37.4/300)** on SWE-bench Lite (`GPT-4 Turbo`) vs **3.00%** for raw shell + RAG ([SWE-agent](https://arxiv.org/abs/2405.15793), accessed 2026-10-18).
3. **AST / Code-Graph Retrieval (`RepoCoder`, `RepoGraph`, `LocAgent`)**:
   - **RepoGraph** (ICLR 2025) constructs a line-level `def`/`ref` graph via tree-sitter, retrieving $k$-hop ego-graphs. Plugged into 4 scaffolds (`RAG`, `Agentless`, `SWE-agent`, `AutoCodeRover`), it boosts SWE-bench Lite resolve rate by **+32.8% relative** (e.g., `Agentless` `27.33% -> 29.67%`) ([RepoGraph](https://arxiv.org/html/2410.14684v1), accessed 2026-10-18).
   - **LocAgent** (Mar 2025) indexes heterogeneous `contain`/`import`/`invoke`/`inherit` graphs with hierarchical BM25 + 3 progressive tools (`SearchEntity` at fold/preview/full detail, `TraverseGraph`, `RetrieveEntity`), matching `Claude-3.5-Sonnet` localization with `Qwen2.5-Coder-32B` (**92.7% file Acc@5**) at **~86% lower cost ($0.09 vs $0.66)** and **+12% Pass@10** issue resolution ([LocAgent](https://arxiv.org/html/2503.09089v1), accessed 2026-10-18).
4. **Trajectory Pruning, Folding & Sub-Agent Isolation (`Observation Masking`, `ReFold`, `RCR-Router`, `PSMAS`, `Anthropic`)**:
   - **Observation Masking** (Aug 2025) masks environment observations older than $M=10$ turns while leaving agent thoughts/actions untouched, cutting cost by **>50%** and matching or beating both raw trajectories and LLM summarization across 5 model configurations on SWE-bench Verified ([Lindenbauer et al.](https://arxiv.org/html/2508.21433v1), accessed 2026-10-18).
   - **ReFold** (Oct 2026) combines cross-turn output deduplication into signature stubs with agent-signaled finished-turn folding, rendered in chunks every $k=3$ steps and backed by lossless `restore <step>`, cutting tokens **18–60%**, KV cache **30–58%**, and cost **up to 45%** with zero accuracy loss ([ReFold](https://arxiv.org/html/2610.07863v1), accessed 2026-10-18).
   - **Sub-Agent Isolation & Routing**: **Anthropic** isolates sub-agent exploration trajectories (10k+ tokens) into **1,000–2,000 token** handoff summaries for a lead `Claude Opus 4` orchestrator (**+90.2%** over single-agent on internal research eval, [Anthropic Multi-Agent](https://www.anthropic.com/engineering/built-multi-agent-research-system), accessed 2026-10-18). **RCR-Router** (Aug 2025) and **PSMAS** (Apr 2026) cut multi-agent coordination tokens by **25–47% (35% mean)** and **21.4–34.8% (27.3% mean)** via role/phase-scheduled memory routing ([RCR-Router](https://arxiv.org/html/2508.04903v1), [PSMAS](https://arxiv.org/abs/2604.17400), accessed 2026-10-18).

## Q2. Does Compression Hurt Small Models More Than Large Ones?

### The Compressor-vs-Reader Scale Asymmetry
External evidence from 2025–2026 reveals a critical distinction between the **compressor/skimmer model** (which scores which code fragments to keep) and the **reader/solver model** (which must reason over the compressed output):

1. **Small models (`0.5B–0.6B`) are strong *compressors/skimmers* when estimating relevance**:
   - **LongCodeZip** (`arXiv:2510.00446v1` §V-C, Table VIII) ablates the compressor model across `Qwen2.5-Coder-0.5B`, `1.5B`, `3B`, `7B`, `14B`, and `32B` on `Qwen2.5-Coder-7B` as the reader. The **0.5B compressor achieves 57.15 ES / 31.60 EM**, nearly matching the **7B compressor (57.55 ES / 32.40 EM)** and **32B compressor (57.82 ES / 32.80 EM)** while running in a fraction of the time ([LongCodeZip](https://arxiv.org/html/2510.00446v1), accessed 2026-10-18).
   - **SWE-Pruner** (`arXiv:2601.16746v1` §3.3) uses `Qwen3-Reranker-0.6B` to score line-level retention probabilities in `<100ms` per 8k tokens, improving downstream agent solve rate on SWE-bench Verified-50 (`62% -> 64%`) ([SWE-Pruner](https://arxiv.org/html/2601.16746v1), accessed 2026-10-18).
2. **Small models (`0.5B–7B`) are fragile *readers* of lossy/abstracted code, whereas frontier models (`GPT-4o`, `Claude-3.7-Sonnet`) compensate via parametric priors**:
   - In **LongCodeZip** (`arXiv:2510.00446v1` §V-A, Tables I–III), when frontier models (`GPT-4o`, `Claude-3.7-Sonnet`) read 4.3x–5.6x compressed prompts, accuracy matches or **exceeds** full uncompressed context (e.g., on RepoQA, `GPT-4o` reaches **88.9** and `Claude-3.7-Sonnet` reaches **90.7**, beating full-context baselines). By contrast, on `DeepSeek-Coder-6.7B` and `Qwen2.5-Coder-7B`, any compressor that drops syntactic glue (`LLMLingua`, `LLMLingua-2`, `Selective-Context`) causes catastrophic drops (`34.72–44.31 ES` vs `57.55 ES` for LongCodeZip) ([LongCodeZip](https://arxiv.org/html/2510.00446v1), accessed 2026-10-18).
   - Crucially, **even LongCodeZip disables intra-function body pruning ($R_{\text{fine}}=1.0$) on RepoQA** (`arXiv:2510.00446v1` §IV-D) because tasks requiring exact function understanding break when internal lines of the target function are stripped ([LongCodeZip](https://arxiv.org/html/2510.00446v1), accessed 2026-10-18).
   - **RepoGraph** (`arXiv:2410.14684v1` §5.2, Table 4) explicitly tests **raw code graph vs LLM-summarized/abstracted code graph**: for a 1-hop graph (which fits in window), **summarization reduces SWE-bench Lite resolve rate from 29.67% to 28.33% (-1.34 pp)** because abstracting code into summaries loses exact implementation details; summarization only helps at 2-hop when raw code overflows the window (`26.00%` raw 2-hop) ([RepoGraph](https://arxiv.org/html/2410.14684v1), accessed 2026-10-18).
   - **LocAgent** (`arXiv:2503.09089v1` §4.2, Table 1) shows fine-tuned `Qwen2.5-Coder-7B` trails `Qwen2.5-Coder-32B` by **-6.5 pp on file localization** (`86.2% vs 92.7%` Acc@5) and **-8.7 pp on function localization** (`71.5% vs 80.2%` Acc@10) even when given structured graph tools ([LocAgent](https://arxiv.org/html/2503.09089v1), accessed 2026-10-18).
3. **Why Context Fabric's `B4` and `B4-v3` small-model readers lost accuracy**:
   - In `B4` (`Qwen2.5-1.5B-Instruct`) and `B4-v3` (`Qwen2.5-0.5B` and `1.5B`), Context Fabric compiled files into **signatures, docstrings, assignments, and imports while stripping function bodies**. `B4-EXPLORE.md` proved that 100% (12/12) of required target symbols were present in the packet, yet `1.5B` scored `21/36` (`0.58`) vs `35/36` (`0.97`) full context because: (a) signature-only stubs look identical across sibling methods (`is_error` vs `is_server_error`), and (b) stripping inline `from X import Y` Context associations forced multi-hop inference that `0.5B–1.5B` models cannot perform without method bodies (`docs/engineering/B4-EXPLORE.md`).

## Q3. Hybrid "Retrieve Then Compress": Who Does It, and Does It Beat Plain Retrieval at Equal Budget?

### How Leading Systems Combine Retrieval and Compression
Three distinct architectures implement "retrieve then compress" in 2025–2026:
1. **Coarse Function Retrieval -> Fine Query-Conditioned Block/Line Pruning (`LongCodeZip`, `SWE-Pruner`)**:
   - **LongCodeZip** first ranks functions by instruction-conditional perplexity to select a coarse pool of budget $B_{\text{coarse}} = B / R_{\text{fine}}$, then chunks each selected function at perplexity spikes and solves a **0/1 knapsack problem** to retain only the highest-AMI blocks within total budget $B=2,000$ tokens ([LongCodeZip](https://arxiv.org/html/2510.00446v1), accessed 2026-10-18).
   - **SWE-Pruner** lets the coding agent execute standard retrieval (`grep`, `find`, file `read` with line ranges) alongside an explicit `context_focus_question`, and passes the raw retrieved text through its `0.6B` line-level neural skimmer before appending to the trajectory ([SWE-Pruner](https://arxiv.org/html/2601.16746v1), accessed 2026-10-18).
2. **Coarse Index / Skeleton Retrieval -> Lossless Selective Expansion (`Agentless`, `LocAgent`)**:
   - Rather than retrieving chunks and compressing them, **Agentless** and **LocAgent** invert the order: retrieve/browse compressed AST skeletons (`fold`/`preview` signatures) across dozens of files, then **decompress (fetch full raw bodies)** only for the 1–5 functions selected for editing ([Agentless](https://arxiv.org/html/2407.01489v1), [LocAgent](https://arxiv.org/html/2503.09089v1), accessed 2026-10-18).
3. **Iterative Retrieval -> Cross-Turn Deduplication & Reversible Folding (`ReFold`)**:
   - **ReFold** leaves the current turn's retrieved file/search outputs intact, but across turns replaces duplicate file views with a reference stub containing only top-level class/function headers (`File <path> (unchanged, full content in step i); top-level definitions: ...`) and folds completed search/debug sub-trajectories every $k=3$ steps ([ReFold](https://arxiv.org/html/2610.07863v1), accessed 2026-10-18).

### Verdict: Does It Beat Plain Retrieval at Equal Budget?
- **YES — when compression is query-conditioned and preserves syntax blocks.** At a ~2,000-token target budget on `Qwen2.5-Coder-7B`, **LongCodeZip** (`2,005` tokens, 4.3x compression) achieves **57.55 ES / 32.40 EM**, beating plain **Function-RAG** (`2,782` tokens, 3.1x compression, **52.79 ES / 26.00 EM**) by **+4.76 ES and +6.40 EM while using 28% fewer tokens** (and also beating BM25/Dense chunk RAG). Similarly, on SWE-bench Verified-50, **SWE-Pruner** (`0.506M` tokens, **64% resolve**) beats plain chunk **RAG** (`0.422M` tokens, **50% resolve**) by **+14 pp** ([LongCodeZip](https://arxiv.org/html/2510.00446v1), [SWE-Pruner](https://arxiv.org/html/2601.16746v1), accessed 2026-10-18).
- **WHY it beats plain retrieval at equal budget**: Whole functions often contain 50–80% boilerplate (logging, error branches, unrelated helpers) alongside 20% task-critical logic. Plain Function-RAG wastes budget on those irrelevant lines, crowding out 2nd- and 3rd-hop helper functions. Query-conditioned block/line pruning strips only the query-irrelevant blocks inside retrieved functions, **packing more cross-file relevant functions into the same 2k–4k budget**.
- **WHY Context Fabric's `B4-v3` lost to plain BM25 retrieval (`7/20` vs `11/20`)**: Our `B4-v3` compiler performed **query-blind static AST extraction** (keeping all signatures across the repo while deleting all function bodies), whereas plain BM25 (`retrieve`) fetched raw 512-token AST chunks **with their bodies intact** for the specific task query (`docs/engineering/B4-V3-RESULT.md`).

## Q4. Where Real Token Costs Come From in Multi-Agent Coding Workflows

### Empirical Breakdown of Coding-Agent Token & KV Spend
Recent empirical studies on SWE-bench, GitHub Copilot production traces, and multi-agent systems provide exact shares of where tokens, dollars, and KV memory go:
1. **Tool outputs — specifically `read` (`cat`/`grep`/`find`) observations — account for 59% to 84% of all tokens**:
   - **Lindenbauer et al.** (`arXiv:2508.21433v1` §1 & §D.4) show that in `SWE-agent` on SWE-bench Verified, environment observation tokens ($o_t$) comprise **~84.0% of an average turn**, vastly outweighing agent reasoning and action generation ([Lindenbauer et al.](https://arxiv.org/html/2508.21433v1), accessed 2026-10-18).
   - **SWE-Pruner** (`arXiv:2601.16746v1` §2, Fig. 2 & Appendix A) breaks down SWE-bench Verified trajectories by tool category: **`read` operations (`cat`, `grep`, `head`, `find`) consume 76.1% of all tokens on `Claude Sonnet 4.5`** (vs **12.1%** `execute`/tests and **11.8%** `edit`) and **67.5% on `GLM-4.6`** ([SWE-Pruner](https://arxiv.org/html/2601.16746v1), accessed 2026-10-18).
   - **ReFold** (`arXiv:2610.07863v1` §2, Fig. 2b) measures peak KV-cache occupancy: **tool outputs occupy ~59% of peak KV cache** under `base`, while agent commands, reasoning traces, and fixed system prompts account for the remaining **~41%** (and become **66–68%** of remaining KV once tool outputs are pruned) ([ReFold](https://arxiv.org/html/2610.07863v1), accessed 2026-10-18).
2. **Long-tail compaction trajectories dominate production fleet spend**:
   - Citing production telemetry across **95 trillion tokens of GitHub Copilot** (`Liu et al., 2026a`, cited in `ReFold` §1), **ReFold** reports that the **7.8% of coding sessions that trigger context compaction consume 44.2% of total fleet token usage** ([ReFold](https://arxiv.org/html/2610.07863v1), accessed 2026-10-18).
3. **Prefix-cache invalidation is the silent dollar killer**:
   - **ReFold** (`arXiv:2610.07863v1` §2, Observation 2, Fig. 2c/e) demonstrates that sliding-window observation masking (`mask`) mutates the historical prompt prefix on every step, collapsing the prefix-cache hit rate from **84% (`base`) to 23%**, which adds **5.1 cents per task (31% of total dollar cost)** in lost cache discounts ([ReFold](https://arxiv.org/html/2610.07863v1), accessed 2026-10-18).
   - **Don't Break the Cache** (`arXiv:2601.06007v1` §4) shows across 500 multi-turn agentic sessions on `GPT-4o`, `Claude Sonnet 4`, and `Gemini 2.5 Flash` that preserving a stable prefix (excluding dynamic timestamps/tool churn from prefix mutations) cuts API cost by **41–80%** and TTFT by **13–31%** ([Lumer et al.](https://arxiv.org/html/2601.06007v1), accessed 2026-10-18).
4. **Multi-agent fan-out multiplies trajectory tokens by ~3.75x over single agents (~15x vs chat)**:
   - **Anthropic** reports that while single agents use **~4x** the tokens of standard chat, multi-agent systems use **~15x** the tokens of chat because parallel sub-agents each build multi-turn search/read trajectories ([Anthropic Multi-Agent](https://www.anthropic.com/engineering/built-multi-agent-research-system), accessed 2026-10-18).

### Verdict: Compiled Static Repo Context vs. Trajectory/Tool-Output Growth
**Agent trajectory growth (specifically `read`/search tool outputs across 20–100 turns) AND prefix-cache preservation are by far the biggest levers** — not one-shot static repo compilation. When a repo slice fits in context, prefix caching already makes repeated reads ~90% cheaper (`PILOT-MECH-RESULT.md` paid only `182` uncached tokens on warm raw cache vs `11,857` when `compile` mutated the prompt per role). Static repo compilation only wins on raw prefill before turn 1; across a 30-turn coding trajectory or 4-agent handoff, **pruning/deduplicating `read` tool outputs (`76.1%` of tokens) without breaking the prefix cache (`84–87%` hit rate)** is the primary cost and KV lever.

## Q5. Most Defensible Product Thesis for Context Fabric in 2026 & Target Benchmark/Metrics

### Recommended 2026 Product Thesis
> **"Context Fabric is a Cache-Aligned Trajectory & Handoff MMU with Cryptographic Provenance for Coding Agents."**  
> Instead of acting as a lossy, query-blind AST body-stripper that replaces raw repo context (and breaks prefix caching across roles), Context Fabric operates as a **three-tier, cache-preserving rendering and governance layer**:
> 1. **Tier 0 (Pinned Shared Prefix Index)**: A deterministic, repo-wide `.cfx` AST + call-graph map (~1k–2k tokens, PageRank-weighted with full `from X import Y` module bindings) that stays **100% byte-identical at the start of every prompt** across all turns and sub-agents to guarantee **85%+ prefix-cache hit rates**.
> 2. **Tier 1 (Query-Conditioned Progressive Disclosure & `read` Skimming)**: Agents localize via Tier-0 signatures (`fold`/`preview`), fetch **uncompressed function bodies** (`RetrieveEntity` / $\pm 10$-line windows) for target symbols, and pass large raw tool outputs (`cat`, `grep`, test logs) through a fast **goal-conditioned line/block skimmer** (`0.5B–0.6B` SWE-Pruner / LongCodeZip style) rather than static body deletion.
> 3. **Tier 2 (Chunked Reversible Trajectory Folding & Signed Multi-Agent Handoffs)**: Across long trajectories and sub-agent handoffs, Context Fabric deduplicates repeated file reads into `ctx://` reference stubs, folds completed sub-goals into **chunked ($k=3$) reversible `CPP v1.0` packets** (supporting 1-step lossless `cfx restore <uri>`), injects negative-knowledge quarantine constraints, and cryptographically seals/verifies every handoff (`cfx verify`, `cfx replay`).

### What Metric and Benchmark Should Prove It
Internal trials (`B4`, `PILOT-MECH`) proved that **billed prompt tokens alone are a vanity metric** when per-role compilation breaks prefix sharing and raises uncached prefill by `1.56x`. In 2026, Context Fabric must be proven on **cache-aware systems + accuracy metrics**:

| **DROP** | **3. Drop Free-Form LLM Trajectory Summarization for Active Agent Loops** | **Lindenbauer et al.** (`arXiv:2508.21433v1`) proved LLM trajectory summarization costs more, takes **+13–15% more turns**, and underperforms simple observation masking, while **ReFold** (`arXiv:2610.07863v1`) showed `compact` adds `3.3s/step` latency and permanently loses ~33% of observation tokens. Use deterministic `ctx://` reference stubs + agent-signaled reversible fold notes instead. |
