## B. Contradicted or Weakened Claims

Empirical testing in Stage B and the post-audit gap wave—specifically [`docs/engineering/B4-RESULT.md`](file:///C:/Users/<user>/orca/workspaces/Context-Fabric/order-b-b7/docs/engineering/B4-RESULT.md) (**KILL** on divergent-role compilation vs. prefix caching) and [`docs/engineering/PILOT-MECH-RESULT.md`](file:///C:/Users/<user>/orca/workspaces/Context-Fabric/order-b-b7/docs/engineering/PILOT-MECH-RESULT.md) (**13.62x** billed reduction, but **11,857 vs. 182** uncached tokens in favor of the cached raw prompt)—directly contradicts or materially weakens several headline claims in the three original reports.

### Top 5 Contradicted Claims (Executive Callout)

1. **Per-role packet compilation beats full-context sharing on both token cost and task quality (`Intro` p.2–3, `Arch` p.3, p.20):** In `B4-RESULT.md` (real `httpx` repo, 3 divergent roles: implementer, test-author, reviewer on `Qwen2.5-Coder-1.5B`), `compile` scored **21/36 (58.3%)** vs. **35/36 (97.2%)** for `broadcast` (full shared prompt) and **29/36 (80.6%)** for `prefix_cache_only`, while burning **13,860 uncached tokens** vs. **8,871 uncached tokens** for `prefix_cache_only` (**1.56x worse**).
2. **"Stop paying to re-ingest the same context into every sub-agent" (`Intro` p.2, p.6):** When a workload fits inside the model's context window and automatic prefix caching (vLLM APC / Anthropic / OpenAI prompt caching) is active, the raw shared prompt is prefilled **once** (`182` uncached tokens across 20 turns after Turn 1 in `PILOT-MECH-RESULT.md`, `99.9%` cache hit rate), whereas dynamic per-turn/per-role packet assembly invalidates prefix cache blocks and forces **11,857 uncached prefill tokens** (`65x` more actual prefill compute than cached raw).
3. **"~15x tokens vs. a single chat — the multi-agent duplication cost we attack" (`Intro` p.1, p.3; `Lit` p.1, p.8):** The `15x` figure is an observational upper bound from Anthropic's unmanaged multi-agent research system, and the repo's own early `15.0x` script (`evals/audit_fixes.py`) was exposed in `VERIFICATION-REPORT.md` (N8) and `AUDIT.md` (GAP-01) as a hardcoded arithmetic identity (`15 * single_tokens`) with an unused model client. Against a prefix-cached multi-agent baseline, Context Fabric reduces *billed* tokens (**13.62x** in `PILOT-MECH-RESULT.md`, **1.68x** in `B4-RESULT.md`) only because cloud providers still charge 10%–50% for cached prefix reads, not because it reduces physical prefill work.
4. **"Smaller, cheaper model given a well-compiled packet can do work that today requires a frontier model drowning in raw context" (`Intro` p.2, p.3, p.4, p.6):** On `Qwen2.5-Coder-1.5B` (`B4-RESULT.md` & `B4-EXPLORE.md`), mechanical AST extraction and per-role compilation *degraded* accuracy by stripping surrounding module patterns and helper conventions that the smaller model relied on for associative synthesis (`21/36` compiled vs. `35/36` raw broadcast). Furthermore, `AUDIT.md` (GAP-08) and `VERIFICATION-REPORT.md` (N21) confirmed that the earlier 0.5B-vs-1.5B test (`93.3%` vs. `93.3%`) was a saturated ceiling artifact on trivial docstring checks, not a demonstration of model-tier arbitrage.
5. **Passing the v1 Quality-Cost Frontier Gate (`Arch` p.20, p.22; `Lit` p.13 RQ5):** `Lit` p.13 explicitly set the falsification rule: *"If full-context or simple top-k retrieval matches quality at comparable cost across representative workloads, the added layer is unjustified."* For workloads that fit within the model's context window (`<=128K` tokens), `B4-RESULT.md` triggered this exact falsification criterion (` verdict: KILL`).

## C. Not Yet Folded In

The following ideas, papers, mechanisms, and evaluation designs from the three original reports were never folded into the repository's active engineering or research docs, and **matter more now** in light of the `B4-RESULT.md` and `PILOT-MECH-RESULT.md` findings.

### 1. Topology Advisor & "Route vs. Share" Consolidation Threshold (`Arch` p.5, p.14; `Intro` p.7)
* **What the reports proposed:** `Arch` p.14 specifies a **Topology Advisor** that monitors cross-agent dependency density, coordination overhead, and missing-dependency retry rates, and automatically recommends consolidating multi-agent per-role routing into a single shared-context execution (or shared prefix broadcast) when task coupling is high.
* **Why it matters now (post-B4):** `B4-RESULT.md` proved empirically that when 3 roles (`implementer`, `test-author`, `reviewer`) operate over a tightly coupled `~8.9K`-token code slice that fits in the model's window, per-role compilation fractures the KV cache (`13,860` uncached tokens vs `8,871`) and drops quality (`21/36` vs `35/36`). Folding in a deterministic **Route-vs-Share gate** in `kernel/router/compiler.py`—e.g., if `total_routable_tokens <= window_prefix_threshold` and all roles share the same security compartment, bypass per-role slicing and emit a single prefix-aligned packet—directly turns the B4 KILL into an automated router policy decision.

### 2. RCR-Router & Multi-Agent Token-Reduction Prior Art (`Lit` p.8, p.15; `Arch` p.4, p.20)
* **What the reports proposed:** `Lit` p.8 and `Arch` p.4/p.20 ground multi-agent routing in **RCR-Router** (*Role-Aware Context Routing for Multi-Agent LLM Systems*, arXiv:2508.04903, 2025), **PSMAS** (*Prefix Sharing Multi-Agent System*, arXiv:2604.17400, 2026 — `27.3%` mean token reduction specifically by aligning prefix order across agents), **S1-MAS** (arXiv:2610.08155, 2026 — `44.9–97.2%` reduction), **SUPERVISORAGENT** (`29.68%` net reduction), and **AgentPrune** (`28.1–72.8%` communication graph pruning). `docs/research/REFERENCES.md` never added RCR-Router, PSMAS, S1-MAS, or AgentPrune.
* **Why it matters now (post-B4 & PILOT-MECH):** PSMAS (`arXiv:2604.17400`) specifically solves the exact failure mode discovered in `B4-RESULT.md` and `PILOT-MECH-RESULT.md`: how to route multi-agent context *without* breaking prefix cache hits across agents. Similarly, RCR-Router's iterative role-aware memory selection and `Arch` p.20 Experiment 1 (*Role-routing replication*) provide a concrete external baseline to diagnose whether B4 failed due to single-shot AST lossiness (`B4-EXPLORE.md`) vs. lack of iterative role-memory updates.

### 3. 4-Stage Compression Verification Gate & Lossless Fallback (`Lit` p.5; `Arch` p.13, p.18)
* **What the reports proposed:** `Lit` p.5 defines a mandatory **4-stage compression gate**: (1) Preserve list (never compress identifiers, signatures, numbers, code), (2) Extractive first, (3) Verify coverage & check for contradiction, and (4) **Fallback to source text** if verification confidence is low (`lossless_fallback` degraded mode in `Arch` p.18).
* **Why it matters now (post-B4-EXPLORE):** `docs/engineering/B4-EXPLORE.md` isolated the root cause of the B4 quality collapse (`21/36` vs `35/36`): `evals/mech_fabric.py` mechanically extracted AST symbol signatures (`kernel/cartridge/extractor.py`) and routed those lossy stubs instead of full implementation bodies when the budget had room, starving the 1.5B model of surrounding implementation patterns. Folding in the `Lit` p.5 **lossless fallback rule**—never substitute an AST stub (`Tier 0`) for raw source (`Tier 3`) when remaining token budget can hold the raw source block—would directly remediate the `B4-EXPLORE.md` failure mode.

### 4. Structured Conflict Sets & Bi-Temporal Contradiction Arbitration (`Arch` p.12, p.18; `Lit` p.7, p.12)
* **What the reports proposed:** When two active blocks have an unresolved `contradicts` edge, `Arch` p.18 specifies routing both inside a dedicated `conflict_set` structure annotated with authority, `valid_from`/`valid_to` timestamps, and verification status so the receiving agent explicitly arbitrates rather than seeing two unmarked conflicting paragraphs. `Lit` p.12 pairs this with a **Temporal Contradiction Evaluation Suite**.
* **Why it matters now:** While `kernel/router/dependency_closer.py` pulls both ends of a `contradicts` edge into the packet and logs a warning in `CompileManifest`, the rendered prompt presented to the LLM via `sidecar/server.py` does not visually bracket conflicting blocks as a structured `conflict_set` with authority/timestamp metadata, nor is there an evaluation script in `evals/` testing whether agents resolve superseded/conflicting requirements correctly. Given that governance, provenance, and state hygiene are Context Fabric's strongest remaining differentiators (`SEAL.md`, `SHARED-COPY.md`), making conflict arbitration visible in the prompt renderer and benchmarked in `evals/` strengthens the non-token-savings value proposition.

### 5. LongMemEval 5-Stage Failure Separation & Unified North-Star Scorecard (`Arch` p.4, p.19–20; `Lit` p.12)
* **What the reports proposed:** `Arch` p.4 and p.20 adopt **LongMemEval** (arXiv:2410.10813, ICLR 2025; `500 questions` across `5 ability categories`) to separate failures into **5 distinct pipeline stages**: (1) Indexing, (2) Candidate recall, (3) Packet packing, (4) Agent reading/use, and (5) Final task outcome, paired with the North-Star metric (`Successful, policy-compliant tasks per 1,000 / 1,000,000 input tokens` — expanding to uncached prefill tokens per `COSTS.md`).
* **Why it matters now:** In `B4-EXPLORE.md`, separating recall (`RECALL-BENCH.md`) from AST extraction vs. packing had to be done via ad-hoc forensic scripts after `B4-RESULT.md` failed. Formalizing the 5-stage diagnostic breakdown and reporting `correct outcomes per 1,000 uncached prefill tokens` alongside `correct outcomes per 1,000 billed tokens` across all `evals/` scripts prevents future confusion between provider billing artifacts and physical compute savings.

### 6. Bounded On-Demand Expansion Protocol (`POST /packets/{id}:expand`, `Arch` p.9, p.13, p.21)
* **What the reports proposed:** `Arch` p.9 (Invariant 7: *Expandable*), p.13, and p.21 define an explicit protocol where omitted or pointer-stubbed blocks include `expansion_handles` (`ptr_...`), and an agent can call `POST /packets/{id}:expand` with `handle_id`, `reason`, and `additional_tokens` to receive a deterministic, hash-chained delta packet.
* **Why it matters now:** Currently, `kernel/mmu/epoch_folder.py` emits `ctx://` pointer blocks and `sidecar/mcp_server.py` offers `fabric_search`, but an agent behind the transparent OpenAI proxy (`sidecar/server.py`) has no first-class expansion endpoint or automatic tool-call interceptor to dereference a `ctx://` pointer or upgrade an AST stub (`Tier 0`) into full source (`Tier 3`) when it realizes details are missing. Adding deterministic handle expansion bridges the gap between compact initial packets and full-source fidelity.

### 2. LMCache Integration Status

`docs/engineering/RUNTIME.md`, `docs/engineering/AGENT-HINTS.md`, and `docs/engineering/ROADMAP-DECISIONS.md` reference LMCache as the target cross-tier KV-cache offloading layer for vLLM.

* **URLs opened (accessed 2026-10-18):**
  * `https://github.com/LMCache/LMCache`
  * `https://docs.lmcache.ai/`
  * `https://docs.lmcache.ai/mp/index.html`
  * `https://docs.lmcache.ai/getting_started/compatibility.html`
  * `https://docs.lmcache.ai/mp/http_api.html`
  * `https://docs.lmcache.ai/mp/kv_cache_management.html`
* **Current Architecture & vLLM Compatibility:**
  * LMCache is an active PyTorch Foundation project (`12.1k` GitHub stars, `2.1k` forks as of 2026-10-18) that shipped its **Multiprocess (MP) Architecture** in April 2026 (`lmcache server` communicating with vLLM over ZMQ/gRPC plus a FastAPI HTTP control plane on port `8080`, replacing the older Legacy In-Process Mode) and promoted multi-node P2P CPU memory sharing to production in January 2026.
  * It integrates natively with vLLM v1 via `--kv-transfer-config` (`LMCacheConnectorV1Dynamic` / `kv_connector_module_path`), supporting L1 (CPU DRAM, Device-DAX, NVMe/GDS) and L2 (NIXL, Mooncake Store, Redis/Valkey, S3, native C++ Rust raw-block plugins) storage tiers.
* **Programmatic Cache Control Surface (Ready Now vs. "Coming Soon"):**
  * **Available Now in MP HTTP API (`https://docs.lmcache.ai/mp/http_api.html`):** The standalone LMCache MP server exposes three live HTTP endpoints that Context Fabric's sidecar could call directly without waiting for vLLM scheduler hints:
    1. `POST /cache/prefetches` — accepts a token ID sequence, computes chunk hashes, and pre-loads matching KV chunks from L2 into L1 ahead of an incoming agent turn.
    2. `DELETE /cache/objects` — deletes/evicts caller-supplied KV keys across L1 and L2.
    3. `PUT /quota/{cache_salt}` (and `GET`/`DELETE`) — enforces per-tenant or per-compartment (`cache_salt`) storage quotas in GB.
  * **Not Yet Shipped in MP Mode (`https://docs.lmcache.ai/mp/kv_cache_management.html`):** The dedicated MP cache-management page explicitly notes *"This page is coming soon. It will cover `pin`, `evict`, `move`, and `compress` operations on cached KV segments via the HTTP API."* Fine-grained `pin`/`move`/`compress` controller actions currently exist only in Legacy In-Process Mode (`LMCache Controller`).
