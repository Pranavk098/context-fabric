## Method

- Join: parent `Agent` tool_use, then `toolUseResult.agentId`, then the child transcript.
- Cost: repo list prices on usage counted once per `message.id` (`cfxd/usage_dedupe.py`).
- Parent knowledge at spawn: paths Read/Edited/Written, Bash commands run, pre-spawn.
- Redundant call: child Read/Grep on a path the parent knew, or a child Bash command identical (whitespace-normalised) to one the parent ran.
- Lower estimate: cost of turns that issued redundant calls, pro-rated by the redundant share of the turn's tool calls. Upper estimate: full cost of those turns plus their results (chars/4 tokens) carried as one cache write and a cache read on every later child turn, capped at child cost.
- Exploration: cost of turns before the first Edit/Write (all turns if it never edits).

## Caveats and bias

- One person's sessions on one machine. Many delegations are research or exploration tasks where the parent has read nothing, so little can be re-read by construction.
- Parent knowledge is only what its own Read/Edit/Write/Bash calls show. Context from the user's prompt, compacted history or MCP tools is invisible, so re-discovery is undercounted.
- Path match is exact after slash/case normalisation. A file under another spelling, and Grep over a directory, are not matched. Bash re-runs need an exact command match.
- Attribution is the hard part. The lower figure ignores that a redundant result stays in context; the upper figure charges the whole turn and its carried results and estimates result tokens from characters. Treat the truth as between them.
- A re-read is not always waste: a child may need the exact bytes in context to edit them.
- Prices are list prices at the repo's `as_of` date; the cache TTL per turn is not known.
