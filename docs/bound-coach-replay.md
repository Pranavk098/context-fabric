## Coach

Method: one Stop per assistant message whose `stop_reason` is not `tool_use`.
Context is input + cache creation + cache read. The shipped rule (context >= 150,000, turn >= 30, cooldown 10 turns, growth >= 100,000 tokens) is replayed unchanged.

- Top 10% of priced sessions: 48 of 473 (cost at the cutoff $7.25)
- Sessions where the nudge would have fired: 17
- **Precision 100.0%, recall 35.4%** against the top 10% (hits: 17)
- Top sessions that reach the nudge's own thresholds (recall ceiling): 17 of 48 (35.4%)
- First nudge turn among fired sessions: median 30, p25 / median / p75 30 / 30 / 30; sessions with more than one nudge: 8

## Caveats

- One person's sessions on one machine. Transcripts are not the hook payload: a Stop is inferred from `stop_reason`, and an interrupted or resumed session can end a turn without one.
- Bound text is the tool_result content, so harness truncation has already happened; the true saving on an untruncated stream is larger. The replay also charges no cache-read saving on later turns, which makes it a lower bound.
- The shipped bound rule rewrites only a bare allowlisted command. The wider variant additionally recognises a test runner inside a compound command; it is a hypothetical extension, not shipped behaviour.
- The error pattern is the WP's literal regex. A head line that matches is not proof the model needed it, and a lost line is not proof the task failed.
- Coach cost includes every priced turn in the session. The top 10% is a rank cut, so ties at the cutoff are not split.
