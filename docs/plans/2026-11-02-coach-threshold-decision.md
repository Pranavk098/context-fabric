# Coach threshold for tester week: frozen setting (2026-11-02)

Dated decision note under `docs/plans/2026-11-01-wave-decisions.md` (W1-06: "the tester setting is picked from the
sweep and frozen before tester week; no retuning on tester data"). Written by the orchestrator before any tester data
exists. The sweep was run on the founder's machine only (tuning set); testers' logs are the held-out set.

## Decision

Fire the coach nudge when a session has reached **turn 15** and its **cumulative cache-read cost has reached $0.50**
(the figure the nudge itself quotes). On the replay this fires in 27 of 463 priced sessions (5.8%), with precision
100% and recall 57.4% against the top 10% of sessions by cost.

## Why this cell and not the F1 maximum

- The F1 maximum (turn 10, $0.25) sits on the **edge of the grid**, so it is not a real optimum; it only says the
  grid should extend lower. Nudging a user ten turns in is also the least credible moment for a "this session is
  getting long" message.
- Turn 15 / $0.50 keeps recall above half while firing in under 6% of sessions, which is enough fires per heavy
  tester for the randomised comparison to have data, without prompting most sessions.
- The current shipped rule (about 150K tokens and 30 turns, precision 100%, recall about 35%) would give the study too
  few fires.

## What this does and does not show

- Precision of 100% is **not evidence that the nudge helps**. The target set is defined by total session cost and
  the rule fires on cost so far, so a high precision is close to guaranteed. It shows only that the rule selects
  sessions that go on to be costly. Whether a nudge changes what the user does is the question the install-level
  randomisation (D-1) exists to answer.
- One machine, 463 sessions; recall will differ on other people's logs. The setting does not move after this note
  without a new dated note.

## Implementation status

`cfxd/coach.py` still fires on tokens and turns, not on cost. Applying this setting is work package W4-01 (below the
line in the wave report); until it lands, tester builds use the old rule and the study should not start.

## Caveats

- *Measured* on one person's transcripts on one machine. It is a replay, not tester data; the tester setting is frozen from this table before tester week and is not retuned afterwards.
- The top 10% is a rank cut, so ties at the cutoff are not split, and a session that never reaches the fire turn can never be recalled (recall ceiling).
- A session counts once, at its first fire. The shipped cooldown between two nudges is not modelled here; it changes exposure, not whether a session fires.
